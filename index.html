Una guía breve para proyectos web compartidos

Un equipo. Un proyecto. Un historial claro.

Git permite que varias personas trabajen sobre el mismo proyecto, con cambios organizados y un historial que ayuda a entender qué ha ocurrido.

Colaborar sin pisarse los cambios

Cada integrante trabaja en una rama propia. Cuando una tarea está lista, sus cambios se revisan y se incorporan a la rama principal. Así, el equipo puede avanzar en paralelo y detectar problemas antes de publicar.

  • Ramas: espacios separados para desarrollar tareas.
  • Commits: puntos de control con una descripción de los cambios.
  • Pull requests: propuestas para revisar e integrar una rama.

El flujo de trabajo

  1. Actualiza tu copia

    Antes de empezar, trae los últimos cambios de la rama principal con git pull.

  2. Crea una rama para tu tarea

    Usa un nombre breve que explique el objetivo, por ejemplo git switch -c mejorar-inicio.

  3. Guarda avances pequeños

    Revisa los archivos con git status, prepara los necesarios con git add y crea un commit con un mensaje claro.

  4. Comparte la rama

    Publica tus cambios en el repositorio compartido con git push -u origin mejorar-inicio.

  5. Revisa e integra

    Abre una propuesta de integración, pide una revisión y resuelve los comentarios antes de incorporarla a la rama principal.

Comandos de referencia

Acciones habituales durante una tarea
Acción Comando Para qué sirve
Consultar el estado git status Muestra los archivos modificados y preparados.
Preparar cambios git add archivo.html Selecciona los cambios que entrarán en el próximo commit.
Crear un punto de control git commit -m "Describe el cambio" Guarda los cambios preparados en el historial local.
Traer cambios compartidos git pull Actualiza la rama actual con los cambios del remoto.
Publicar una rama git push Envía los commits locales al repositorio remoto.

Acuerdos que ahorran problemas

  • Actualiza tu rama antes de empezar a trabajar.
  • Dedica cada rama a una tarea concreta.
  • Escribe mensajes de commit que expliquen el cambio, no solo "actualización".
  • No incluyas contraseñas, claves privadas ni archivos temporales en el repositorio.
  • Revisa el diff antes de confirmar o compartir cambios.
  • Si aparece un conflicto, habla con quien modificó ese archivo y resuélvelo antes de continuar.

Preguntas frecuentes

¿Qué hago si mi rama se ha quedado desactualizada?

Guarda o confirma tu trabajo y trae los cambios recientes de la rama principal. Si el proyecto usa otra estrategia de ramas, sigue el acuerdo del equipo.

¿Qué significa tener un conflicto?

Git no puede combinar automáticamente dos cambios incompatibles en la misma zona. Hay que revisar ambas versiones, decidir el resultado y confirmar la resolución.

¿Dónde puedo consultar la documentación oficial?

La documentación de referencia está disponible en git-scm.com/doc.
